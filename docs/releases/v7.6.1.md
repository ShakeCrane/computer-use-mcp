# v7.6.1 — the review fixes and the desktop status card

Released 2026-10-11. From [the 2026-10-11 three-pass review](https://github.com/zavora-ai/computer-use-mcp/blob/v7.6.1/docs/reviews/2026-10-11-end-to-end-review.md)
of 7.6.0 (§7, the 7.6.1 list) and its task record in
[`docs/specs/v7.6.1-fixes/tasks.md`](https://github.com/zavora-ai/computer-use-mcp/blob/v7.6.1/docs/specs/v7.6.1-fixes/tasks.md).

## New: a person can see, pause and stop the agent

Set `COMPUTER_USE_STATUS_CARD=true` and a small always-on-top card appears on the first desktop action, on macOS and
Windows: "Agent is using this Mac · 1:42", the current action as the server resolved it ("click (640, 410) in TextEdit ·
Untitled"; typed text is never shown), the last few actions, and **Pause / Resume** and **Stop**.

- Pause refuses new mutating calls with `paused_by_user` and aborts the one in flight; reads keep working.
- Stop does the same for the rest of the session (`stopped_by_user`) and trips the native emergency-stop latch, so a
  drag or a hold stops mid-gesture.
- The card is excluded from screen capture on both platforms, so the agent never sees its own controls; it watches the
  server's pid, so a crashed server leaves nothing on screen; it says when the agent is waiting for you to stop typing
  or for an approval.
- `control_status` (core, read-only) tells the model the state; `doctor` reports `status_card`; the instructions explain
  the two refusals. Linux has the state machine and the tool; no card yet.

The Windows card descends from [PR #40](https://github.com/zavora-ai/computer-use-mcp/pull/40) by
[@ShakeCrane](https://github.com/ShakeCrane); the macOS card is a Swift panel compiled on first use like the capture
helper. Opt-in in this release.

## Fixed

- `screenshot {full_screen: true}` captures the screen; it was advertised in 7.6.0 and never read.
- `unhide_app` is in every profile and apps hidden by `prepare_display` are restored when the session ends; the default
  profile could hide the person's apps with no tool to restore them. The default macOS list is 40 tools.
- Unknown arguments are refused by name with the nearest declared one; a `taget_app` typo used to send input to the
  wrong window. The click aliases keep accepting `click`'s targeting.
- The `click_element` coordinate fallback goes through the user-active guard and coordinate validation.
- Sensitive-label redaction matches whole words: "Shipping address", "Compass" and "Pinned tabs" keep their values.
- `scroll`, `left_mouse_down/up`, `multi_select` and `multi_edit` validate coordinates like `click`.
- Actions that did nothing are errors: `open_application` not activated, `hide_app`/`unhide_app` with no app,
  `activate_window` with no window or not raised. macOS `activate_window` observes the frontmost app instead of
  asserting; Windows `write_clipboard` and UIA `click_element`/`press_button` report failures instead of success.
- The run console host validates Host and Origin on every route, requires JSON POST bodies and caps them, and the page
  accepts messages only from its own iframe; `run_say` no longer takes a role the model could use to speak as the person.
- The Swift capture helper compiles without the first caller's abort signal; Windows `get_app_capabilities` reports the
  accessibility probe; `click_text` refreshes the desktop resources; the instructions say what results verify today.
- `package.json` ships `dist/` as a directory (a hand-written list left PR #40's module out of the tarball); the release
  job tolerates an already-staged version; the "native binary missing" error no longer names unpublished packages; the
  Linux AT-SPI bridge finds a window by PID and loose title and returns a typed error with what it saw.

## Upgrading

- A misspelled argument is now an `invalid_arguments` error naming the nearest valid one; nothing a correct call sends
  changes. `open_application`, `hide_app`, `unhide_app` and `activate_window` return `isError: true` when they did
  nothing; agents that read `activated: false` from a success result should read the error instead.
- Hosts that passed `role: "user"` to `run_say` must record user turns through the console page or the store.
- `tools/list` for the default profile grows by two tools (`unhide_app`, `control_status`).

## Known limits

- The Windows card and the two Windows native fixes were type-checked for `x86_64-pc-windows-msvc` and not run on a
  Windows desktop in this release; a report from one is welcome.
- The card is opt-in; the default is the question for 7.7, with the honest-actions contract (`effect`, `route`,
  `delivery` on every result) that the instructions still describe ahead of the code.

## Evidence

- Unit suite: 560 tests, 559 pass, 1 skipped, on macOS; lint and `cargo check` (macOS and Windows targets) clean.
- Live on this Mac: `npm run integration:macos`, 25 checks: Calculator driven by accessibility, the card's Pause, Resume
  and Stop pressed as a person would, a mutation refused while paused, the card absent from a full-screen screenshot,
  Stop tripping the native latch, nothing left on screen after close.
- A Rust agent on ADK-Rust and Claude (`agents/adk-anthropic-agent`) ran one task against this build with the card on.
